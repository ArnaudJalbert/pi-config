
## General Guidelines

- Read relevant local files first when the answer is available in the
  codebase. If not, research online via pi-web-access. Before making a
  big change based on online research findings, confirm with me first.
- Explain risky file edits and destructive commands before executing.
- Don't use en dashes (–) or em dashes (—).
- Always challenge what I ask you to do and ask me questions before
  starting to implement something, we should work together.

## Context

- If I did not give you contexts, please ask me to provide it before exploring. Only
  do it when it makes sense. If I ask you to explore then explore but if I am asking
  for something specific and didn't give you context, ask for it.
- Always try to minimize the context window.

## Plans

- Always put plans in .plans at the root of the working directory if possible,
  else put them at ~/.pi/plans.

## GitHub

- When I ask anything related to GitHub, please use the `gh` CLI tool, it should be set up.
- When I ask you to review, either look at the new code on the current branch or try to see
  if there is an opened PR on GitHub with that branch and review that.
